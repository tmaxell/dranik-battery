# dranik-battery

Открытая, легковесная альтернатива [AlDente](https://apphousekitchen.com/) для MacBook на Apple Silicon.

Цель первой версии — сделать ровно две вещи и сделать их безопасно:

1. **Ограничение заряда** — не давать батарее заряжаться выше заданного порога (по умолчанию 80 %).
2. **Контроль питания** — наблюдать за состоянием батареи и адаптера: процент, ток, напряжение,
   мощность на входе, температура, износ, число циклов.

Всё остальное (принудительный разряд, калибровка, sailing mode, GUI, расписания) — за пределами
первой итерации.

## Статус

🚧 Реализован слой доступа к SMC, снимок состояния батареи, CLI `dranik` и
инструмент проверки затвора зарядки.

**`dranik` не пишет в SMC.** Единственное, что умеет записывать — отдельный исполняемый файл
`dranik-gate-experiment`, который надо вызвать по имени и от root. Он отвечает на единственный
вопрос, на котором заблокирован остальной проект: действительно ли запись `01 00 00 00`
в `CHTE` останавливает зарядку на этой машине.

Собственно ограничение заряда — демон с гистерезисом — появится после того, как эксперимент
даст ответ.

## Сборка и запуск

```bash
make build
make test
make status
```

```
$ dranik status

  Charge                  100 %

  Health                  92.4 % (4716 / 5103 mAh)
  Cycles                  170
  Temperature             30.4 °C
  ...

Charge control
  Charge gate             CHTE (single key)
  Hardware 80 % limit     no
  Adapter control keys    CH0J, CHIE
  CHTE reads              0
```

Команды:

| Команда | Что делает |
|---|---|
| `dranik status [--json]` | Состояние батареи, возможности управления зарядкой, потребление |
| `dranik smc <KEY>...` | Чтение конкретных SMC-ключей, например `dranik smc CHTE B0AV` |
| `dranik smc --dump` | Полный перебор всех SMC-ключей в TSV |
| `dranik help` | Справка |

Root для `dranik` не нужен: чтение SMC работает от обычного пользователя.

## Проверка затвора зарядки

```bash
make gate-dry-run
```

Прогоняет весь сценарий, **ничего не записывая** — проверяет, что механика отката работает.
Привилегий не требует.

```bash
make gate-experiment
```

Настоящий опыт. Требует root и подключённого адаптера при идущей зарядке. Закрывает затвор,
15 секунд наблюдает за `IsCharging` и `NotChargingReason`, затем открывает его обратно.
Зарядка прерывается примерно на 30 секунд.

Откат регистрируется **до** первой записи — по сигналу и по таймеру. Прервать опыт `Ctrl-C`
безопасно: затвор откроется, а не останется закрытым. Дедлайн жёстко ограничен 120 секундами,
и никакой аргумент не может отодвинуть его дальше.

## Структура

```
Sources/
  CDranikSMC/          Раскладка SMCParamStruct — в C, чтобы её гарантировал компилятор
  DranikSMC/           Доступ к AppleSMC: зондирование, чтение, охраняемая запись
  DranikPower/         Публичный IOKit: снимок AppleSmartBattery
  dranik/              CLI (не пишет в SMC)
tools/
  GateExperiment/      Единственное, что пишет в SMC. Отдельный бинарь, только по имени
  smcprobe.c           Точечная read-only проба — эталонная реализация
  smcdump.c            Полный перебор ключей — эталонная реализация
Tests/
  DranikSelfTest/      Набор тестов
```

### Про запись в SMC

Записать можно только через `SMCConnection.write(_:bytes:matching:)`, и он отказывает, если:
ключа нет; его метаданные (размер, тип, атрибуты) разошлись с ожидаемыми; ключ не помечен
записываемым; длина данных не совпадает. После записи ключ перечитывается и сравнивается —
Battery-Toolkit наблюдал ключи, возвращающие значение, не совпадающее ни с прежним,
ни с записанным.

Проверка метаданных — не формальность. Прошивка уже один раз перенесла управление зарядкой
(`CH0B`/`CH0C` → `CHTE`), и ключ с уехавшим описанием может означать что-то другое.

### Почему тесты — исполняемый файл, а не `swift test`

XCTest живёт в Xcode, а `xcode-select` указывает на Command Line Tools, поэтому импортировать
его нельзя. Вместо того чтобы делать Xcode обязательным или тянуть сетевую зависимость,
набор тестов — обычный исполняемый файл: `make test`, ненулевой код возврата при провале.

Утверждения названы так же, как в XCTest, чтобы переход был механическим.

Пакет зафиксирован на `swift-tools-version: 5.10`, чтобы собираться обоими тулчейнами,
которые есть на машине: CLT (Swift 6.0.3) и Xcode 15.4 (Swift 5.10). Проверено обоими.
